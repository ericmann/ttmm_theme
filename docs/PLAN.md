# These Things Matter build plan
Derived from docs/SPEC.md v0.2 on 2026-09-20. SPEC.md wins over this file.

## Decisions
- Phases → SPEC §8 defines Phases 0–8; this plan follows them in that order, unmerged. Each phase ends with a push task that records `Manual check: NOT VERIFIED (human)`.
- Q4 Books storage → **option repeater `ttm_books`** (SPEC §5.3 shape) edited on a settings tab. `ttm/book-grid` is the only consumer, no book permalinks are designed, and a CPT would have to be excluded from every post query (cells, search, feeds, `ttm/story-tiles`) — more code than a ~150-line repeater form.
- Plugin composition root → `plugins/ttm-core/src/Plugin.php` (`Plugin::boot()`, already called by `ttm-core.php`) holds the ordered module list; every module exposes `public static function register(): void`. It is the only file allowed to import from every directory in SPEC §4.2.
- Admin settings shell → `src/Admin/Page.php` (menu entry Settings → These Things Matter, tab registry, nonce/capability plumbing) and `src/Admin/General.php` (`ttm_settings` form). SPEC §4.2 has no home for the page itself; `Admin/` imports only `Config` and `Support`. Books, Verse and Newsletter register their tabs from their own modules.
- Integration PHPUnit config → stays at `tests/integration/phpunit.xml.dist` (already wired into `npm run test:integration` and `.wp-env.json`). SPEC §4.1's root `phpunit-integration.xml.dist` is not created.
- Fixtures inside wp-env → `.wp-env.json` gains the mapping `"wp-content/ttm-fixtures": "./docs/fixtures"`, so the seeder and integration tests read `WP_CONTENT_DIR . '/ttm-fixtures/...'`. Seed definitions live in `docs/fixtures/seed/*.json` (SPEC Appendix C).
- Block file layout → SPEC §4.1 `plugins/ttm-core/blocks/<name>/{block.json,render.php,index.js}` is kept. A root `webpack.config.js` extends the wp-scripts config with one entry per block (`blocks/<name>/index`) plus the editor bundle (`index`), output `plugins/ttm-core/build/`. `block.json` uses `"editorScript": "file:../../build/blocks/<name>/index.js"` and `"render": "file:./render.php"`; `Blocks\Registrar` registers from the source directory and strips `editorScript` via `block_type_metadata` when `build/blocks/<name>/index.asset.php` is missing, so the front end works without a build.
- `@wordpress/*` editor packages → added as **devDependencies** when first imported (P1-07). wp-scripts maps them to `wp.*` externals at build time; they are needed only so ESLint (`import/no-unresolved`, `import/no-extraneous-dependencies`) and Jest resolve them. `dependencies` stays `{}` (SPEC rule 31).
- Template routing → block themes resolve templates through `single_template_hierarchy` / `category_template_hierarchy`; `Templates\Hierarchy` uses those (SPEC §6.4 names the classic `single_template` / `category_template` filters, which only see `template-canvas.php` in a block theme).
- `ttm/pagination-label` → registered as a binding source (SPEC §6.3) for paragraphs **and** applied to `core/query-pagination-next` / `-previous` through `render_block_core/...` filters in `Query\Archive`, because core pagination blocks accept no bindings. Both read the main query.
- Verse endpoint → `TTM\Core\Verse\Fetcher::ENDPOINT` is the single outbound literal (rule 16). `Config` `verse.endpoint` defaults to the same string; `Fetcher::endpoint()` uses the config value only when its host equals `ENDPOINT`'s host, else `ENDPOINT`. A unit test asserts the two strings are identical.
- Journal derived excerpt (03 §5) → `src/Query/JournalExcerpt.php` filters `get_the_excerpt` for posts whose primary category is Journal and whose manual excerpt is empty, using `Support\Text::sentence_excerpt` and `journal.excerpt_words`; `excerpt_more` is `''` for those posts.
- `ttm/relative-date` rule (03 §13 vs F7 example) → same day "Today · Sept 20"; previous day "Yesterday · Sept 19"; within `journal.relative_day_window` (6) days "Thursday · Sept 18"; older but within `journal.rail_window_days` (30) "Sept 3"; older than 30 days always "Aug 3, 2026" (year shown even in the current year, F7).
- `ttm/category-count` `format` arg values → `articles` ("431 articles →", `_n()`) and `short` ("431 →"); 0 → "All →" (F25). Avoids arrows inside JSON block attributes.
- Fonts → Google Fonts serves Archivo per unicode range, so the theme ships up to 8 woff2 files (`archivo-{400,600,800,400i}-{latin,latin-ext}.woff2`) with `unicodeRange` in `theme.json` `fontFace`; only 400-latin and 800-latin are preloaded. Deviation from 04 §8's "3–4 files" is recorded under Spec issues.
- Phone nav (Q19) → inner mastheads use `core/navigation` with `"overlayMenu":"always"`, `"hasIcon":false` (core renders a text "Menu" toggle and its own overlay script); theme CSS un-overlays it at ≥ 721px. The front masthead uses `"overlayMenu":"never"` and a scroll row ≤ 720px. `assets/js/nav.js` only mirrors the open state onto `<html class="ttm-nav-open">` for CSS and closes on link click; no network.
- Image sizes → the theme's `inc/image-sizes.php` holds the four sizes from 01 §6 as a local array passed through `apply_filters('ttm_image_sizes', …)`; the plugin's `Config` `images.sizes` is what blocks use for `wp_get_attachment_image` size names. Rule 24 (no bare numerals outside `Config.php`) is read as governing `plugins/ttm-core/`; theme PHP may hold design numbers only in `inc/image-sizes.php`.
- Jetpack in tests → integration tests never install Jetpack; they register a stub `jetpack/subscriptions` block with a render callback to exercise the provider switch. The seed (`wp ttm seed`) installs Jetpack in wp-env only for manual review (P7-04 verifies the unconnected-render assumption).
- Seed images → generated at seed time with GD (`imagecreatetruecolor`, neutral fill, label text) and sideloaded; no binary fixtures in the repo. If GD is missing, posts seed without images (fallbacks F8/F12 then show).
- Config keys not in SPEC §5.4 but required by §5.3 → added: `journal_in_main_feed = true` (Q7), `comments_enabled = false` (Q8), `newsletter.list_id = ''`.
- Tuning of ⚠️ ASSUMPTION keys → one measured tuning task per concern at the point the keys first matter: `series.max_purchase_links` (P1-14), `cssBudgetBytes` (P2-03), `series.hub_featured_parts` (P6-02), cache trio (P7-05), newsletter trio (P7-06), Jetpack unconnected render (P7-04), jsdom sufficiency (P8-01 spike).
- Test clock → every integration test that renders dates pins `ttm_now` to `2026-09-20 12:00:00 America/Los_Angeles` (a Sunday) through `TTM_IntegrationTestCase::set_now()`; seed dates are relative to `Clock::now()` at seed time.
- `docs/HANDOFF.md` → written by P8-08 (SPEC Phase 8 "Final HANDOFF.md lists every manual check") if the run's own hand-off step has not already created it.
- `bash scripts/forbidden-patterns.sh` → added to the per-task `verify` set (cheap, already in CI) so the SPEC §3 greps run after every task; P7-07 extends it.
- WP-CLI commands → each command class has a WordPress-independent-of-`WP_CLI` core: `public function run( array $args, array $assoc ): array` returning `['ok'=>bool,'rows'=>[],'messages'=>[]]`; the `WP_CLI` wrapper prints. Integration tests call `run()` directly, so commands are tested without the CLI runtime.
- Politics in cells (03 §1) → Opinion cell meta appends "· Politics" when the post is in the category whose slug is `sections.politics_slug` (child of Opinion after migration); tags are not consulted.
- Branch → `poc/2026-09-20` from `poc` (foundry.json `branchPrefix` `poc/`, `baseBranch` `poc`).

## Conventions
- Commit title `<ID>: <title>`; body sections `Goal:`, `Tests:`, `Interpretation:`, `Measurement:` (tuning tasks only), `Manual check:`. Commits are unsigned (SPEC non-goal). One commit per task.
- `verify` set (run after every task): `composer lint`, `composer test:unit`, `npm run lint`, `npm run test:unit`, `npm run build`, `bash scripts/forbidden-patterns.sh`. Tasks touching `plugins/ttm-core/`, `themes/ttm-theme/` or `tests/integration/` also run `npm run test:integration` (wp-env must be running: `npx wp-env start`).
- PHP: `declare( strict_types=1 );`, WordPress coding standards (tabs), PSR-4 `TTM\Core\` under `plugins/ttm-core/src/`, theme code in namespace `TTM\Theme`. Every user-facing string through `__()`/`esc_html__()`/`_n()` with text domain `ttm-core` (plugin) or `ttm-theme` (theme).
- Unit tests: `tests/unit/<Dir>/<Class>Test.php`, namespace `TTM\Tests\Unit\<Dir>`, extend `TTM\Tests\Unit\TestCase` (Brain\Monkey; WordPress functions stubbed in `TestCase::setUp()`; no WordPress loaded). Integration tests: `tests/integration/<Dir>/<Name>Test.php`, global namespace, extend `TTM_IntegrationTestCase` (created in P1-01; extends `WP_UnitTestCase`). Block tests live in `tests/integration/Blocks/`.
- Block contract (SPEC §6.1, rule 25), restated in each block task: files `plugins/ttm-core/blocks/<name>/block.json`, `render.php`, `index.js`; `block.json` has `"apiVersion": 3`, `"name": "ttm/<name>"`, `"category": "ttm"`, `"textdomain": "ttm-core"`, `"supports": {"html":false,"align":false,"color":false,"typography":false,"spacing":false}`, `"render": "file:./render.php"`, `"editorScript": "file:../../build/blocks/<name>/index.js"`, attribute `"previewState": {"type":"string","default":"normal","enum":["normal","empty","thin"]}`; wrapper `<div <?php echo get_block_wrapper_attributes( [ 'class' => 'ttm-<name> …', 'data-ttm-block' => '<name>' ] ); ?>>`; nothing to render → `return;` before any output (empty string); `previewState` honoured only when `TTM\Core\Blocks\Helpers::is_editor_preview()`; `index.js` registers with `registerBlockType( metadata, { edit, save: () => null } )` using `ServerSideRender` and the shared `PreviewStateControl` from `plugins/ttm-core/src/editor/PreviewStateControl.js`; no inline `style="` except `grid-column`, `aspect-ratio`, `--ttm-*`; no colours, sizes or fonts in markup.
- Rendering a block in tests: `$html = ( new WP_Block( parse_blocks( '<!-- wp:ttm/<name> {"attr":1} /-->' )[0], [ 'postId' => $id, 'postType' => 'post' ] ) )->render();`. Rendering a template: `do_blocks( get_block_template( 'ttm-theme//<slug>' )->content )`.
- Config: every tunable is `Config::get( 'dotted.key' )`; tests override with `add_filter( 'ttm_config', fn( $c ) => array_merge( $c, [ 'key' => v ] ) )` and call `Config::reset()`.
- Clock: every "now" is `Support\Clock::now()`; every parse of a stored date is `Support\Clock::at( string $mysql_datetime )`; every timestamp conversion is `Support\Clock::from_timestamp( int )`.
- Docs are read-only except where a task names a docs file under Files touched (`docs/fixtures/seed/`, `docs/spikes/`, `docs/MIGRATION.md`, `docs/SETUP.md`, `docs/HANDOFF.md`, `docs/PROGRESS.md`).
- "Files touched" lists are the allowed write set for the task; test files for the task are always allowed.

### P0-03: Dates, Text and Html helpers
**Goal:** Provide the pure formatting helpers every block and binding will use: 4-letter "Sept" dates, relative day names, word counts, sentence-trimmed excerpts, curly quotes and escaped HTML fragment builders.
**Files touched:** `plugins/ttm-core/src/Support/Dates.php`, `plugins/ttm-core/src/Support/Text.php`, `plugins/ttm-core/src/Support/Html.php`, `tests/unit/Support/DatesTest.php`, `tests/unit/Support/TextTest.php`, `tests/unit/Support/HtmlTest.php`.
**Design constraints:** SPEC §4.2 (`Support` imports only `Config`), rule 9 (no clock reads: every method takes `DateTimeImmutable` arguments), rule 24 (word window, wpm and day window come in as arguments; callers pass `Config` values), rule 32. 03 §13 formats: `Dates::short_month(DateTimeImmutable $d): string` ("Sept", otherwise PHP `M`); `Dates::short(DateTimeImmutable $d, DateTimeImmutable $now): string` → "Sept 19", or "Jul 30, 2025" when the year differs from `$now`; `Dates::short_with_year($d)` → always "Aug 3, 2026"; `Dates::full($d)` → "September 19, 2026"; `Dates::compact($d)` → "Sun, Sept 20, 2026"; `Dates::masthead($d)` → "Sunday, September 20, 2026"; `Dates::weekday($d)` → "Sunday"; `Dates::relative_day(DateTimeImmutable $d, DateTimeImmutable $now, int $window): ?string` → `__('Today')` same calendar day, `__('Yesterday')` previous day, weekday name when `$d` is within `$window` days before `$now`, else `null`; `Dates::days_between($a, $b): int` (calendar days, site tz). `Text::word_count(string $content): int` strips `<!-- wp:code -->…<!-- /wp:code -->` and `<!-- wp:preformatted -->…` blocks, `<pre>…</pre>`, shortcodes (`[name …]…[/name]` and `[name …/]` by regex, no WP call), all tags and block comments, decodes entities, counts `\S+` tokens (unicode). `Text::sentence_excerpt(string $text, int $words): string`: strip tags; take the first `$words` words; if the last word ends a sentence (`.`, `!`, `?`, `…`, optionally followed by a closing quote/bracket) return them; else extend up to `$words + 15` words to the next terminator and return up to it; else cut back to the last terminator that leaves at least `intdiv($words, 2)` words; else return the first `$words` words followed by `…`. `Text::curly_quotes(string $s): string` converts straight double quotes to “ ” (opening after start/whitespace/`(`/`[`), straight single quotes to ’ (after a word character) or ‘ (elsewhere); leaves text inside `<…>` tags untouched. `Text::reading_minutes(int $words, int $words_per_minute): int` = `max(1, (int) ceil($words / $wpm))`. `Html::el(string $tag, array $attrs, string $inner = ''): string` (attrs escaped with `esc_attr`, `href`/`src` with `esc_url`; `$inner` is already-escaped HTML), `Html::text(string): string` (`esc_html`), `Html::link(string $url, string $label, array $attrs = []): string`, `Html::classes(array $flags): string` (keys whose values are truthy, joined).
**Acceptance tests:** `DatesTest`: `test_short_month_returns_sept_for_september`, `test_short_month_keeps_three_letters_otherwise`, `test_short_adds_year_when_year_differs`, `test_compact_format`, `test_masthead_format`, `test_relative_day_today_yesterday_weekday_and_null` (uses now = 2026-09-20 12:00 America/Los_Angeles; 2026-09-18 → "Thursday"; 2026-09-13 → null with window 6). `TextTest`: `test_word_count_ignores_code_blocks_shortcodes_and_tags`, `test_sentence_excerpt_returns_whole_sentence_without_ellipsis`, `test_sentence_excerpt_extends_to_sentence_end`, `test_sentence_excerpt_cuts_back_to_earlier_sentence`, `test_sentence_excerpt_appends_ellipsis_when_no_boundary`, `test_curly_quotes_pairs_double_quotes_and_apostrophes`, `test_reading_minutes_rounds_up_and_floors_at_one`. `HtmlTest`: `test_el_escapes_attributes_and_urls`, `test_link_builds_escaped_anchor`, `test_classes_joins_truthy_flags`.
**Out of scope:** Any WordPress hook; block rendering; i18n of weekday names beyond `$d->format('l')` (site is English; wrap weekday output in `__()` is not required).
**Verification:** `verify` set.

### P0-05: Self-hosted Archivo fonts, theme enqueue and base CSS
**Goal:** Ship Archivo (400/600/800/400 italic, latin + latin-ext) inside the theme, enqueue `ttm.css`/`editor.css`/`nav.js`, and lay down the resets from 04 §2 without any Google Fonts request.
