Derived from docs/SPEC.md v5.0 on 2026-09-24. SPEC.md wins over this file.

- Phases → SPEC §8's five phases (0 Harness and hygiene, 1 Photographs, 2 Demo WXR/options/blueprint/Playground check, 3 README/screenshots/release workflow, 4 Close-out), in order, never merged. Each phase ends with a task that takes the owner screenshots, commits, pushes and logs `Manual check: NOT VERIFIED (human)` naming what to open.

## Conventions
- Commit message: title `<ID>: <title>`; body `Goal:` / `Tests:` / `Interpretation:` / `Measurement:` (tuning only) / `Manual check:`; template in `CLAUDE.md`.
- After every task run `docs/foundry.json` `verify` plus `extraVerify` for touched prefixes. Docker is needed for integration, e2e, drill, `demo:build`. Stale wp-env after a branch switch: `npx wp-env stop && npx wp-env start`. If `php` on `PATH` is a wrapper shim that fails, run composer as `/usr/bin/php $(command -v composer) <script>`.
- "Un-fixme row X" means: in `tests/e2e/fidelity.spec.mjs` change that row's `test.fixme(` to `test(`, delete its `// P<n>-<nn>` tag, make it pass; never delete a row. Test names are `'<id>: <selector> @<viewport>'`. Text compares use the `text()` helper in `tests/e2e/lib/style.mjs`.
- Row-to-task map: `name-footer`, `name-masthead` → P0-02 (added green) · `demo-lead-photo`, `demo-cells-photo`, `demo-article-hero`, `demo-about-portrait`, `demo-tile-cover`, `demo-alt` → P1-05.
- Pure script modules (`scripts/lib/*.mjs`, `scripts/demo/lib/*.mjs`, `scripts/release/lib/*.mjs`) take paths and data as arguments, never use `import.meta` or top-level `await` (Jest transforms them to CommonJS), never touch the network, never import `sharp`. Jest tests live in `scripts/test/*.test.js`. CLI scripts resolve paths from `process.cwd()` (the repo root).
- CLI command cores return `['ok' => bool, 'rows' => [...], 'messages' => [...]]` and are tested directly (`( new XCommand() )->run( $args, $assoc )`), never through `WP_CLI`.
- Config keys are read through `Config::get( 'key', <default> )` with the default equal to `Config::defaults()` (`ConfigFallbacksTest`), or through the two new accessors for the author keys; `tests/unit/ConfigTest.php` lists every key.
- Synthetic fixtures only (rule 47): tests imitate markup shapes, never a live post's text. Demo prose, captions and alt text are original and CC0.
- Every CSS change (none is expected) goes under its `01 §4` header in `ttm.css`; `ttm.css` ≤ 63488 bytes; no hex literals.
- The `## Log` entry for a task lists rows un-fixme'd, interpretation choices, measurements and `Manual check:` (or `none`).

### R2-01: demo:check stops the whole Playground process tree; no orphaned server after exit
**Goal:** After `npm run demo:check` (no --keep) exits, no `@wp-playground/cli` server or worker process from that run is still alive or listening, and --keep leaves a server that is independent of the exited parent and stoppable by a printed command.
**Files touched:** scripts/demo/check.mjs, scripts/demo/lib/server-process.mjs, scripts/test/demo-server-process.test.js, scripts/test/fixtures/spawn-tree.mjs, docs/HANDOFF.md, docs/PROGRESS.md, docs/spikes/P2-01.md
**Design constraints:** SPEC §3.2 rules 54 and 57, §6.4. Review round 2 F1. Today `spawn( 'npx', [ '@wp-playground/cli', 'server', … ] )` builds a tree npm exec -> sh -> node wp-playground-cli -> node --experimental-wasm-jspi worker, and `playgroundProc.kill()` signals only npm exec, so the CLI server and its worker are reparented to init. - `startServer( command, args, { logFile? } )` spawns with `detached: true`, so the child leads its own process group. Prefer `process.execPath` + the resolved `@wp-playground/cli` bin (`wp-playground.js`) over `npx`/`sh`.
- `stopServer( proc, { graceMs } )` sends SIGTERM to the whole group (`process.kill( -proc.pid, 'SIGTERM' )`), awaits `exit` up to a bounded grace, then sends SIGKILL to the group. It resolves only once the group is gone.
