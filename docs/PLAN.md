## Conventions

## Spec issues
1. **Rule 34 amendment vs. `verify`.** "Phase 0 removes the four glob lines so the lint fails loudly until each phase lands" cannot coexist with `npm run lint` in `verify` after every task. Resolved by the tagged `# P<n>-<nn> pending` lines (Decision "Harness during the flight"); the same applies to `check-fixme.mjs`, which today fails on any `test.fixme(` but §6.9 asks Phase 0 to add ~190 of them. Suggest SPEC say "pending lines tagged with the owning task; empty at flight end".
2. **Rule 44 slug.** `article-h2` still generates `--wp--preset--font-size--article-h-2` (WordPress hyphenates every letter/digit boundary, exactly the `h2`→`h-2` bug). The plan keeps SPEC's slug and makes the checker compute generated names; a slug without a digit (e.g. `article-heading`) would avoid the hyphen entirely.
3. **"Series" in the nav on singles.** §6.1.1 says the current section on singles is the post's primary category; `Nav\CurrentSection` also marks `/series/` current for a post in a series (phase 1 P2-06), which would fail `nav-hub` on the seeded article. The plan removes that branch (Decision "Nav current section"); SPEC could state it.
4. **`core/post-terms` order.** SPEC expects "Technology · Security" from `core/post-terms`, but WordPress orders terms by name. Resolved by a `get_the_terms` filter ordering primary-first then nav order; SPEC could name the mechanism.
5. **Featured-image caption.** `core/post-featured-image` has no caption output; the plan injects a `figcaption` through a render filter (Decision "Featured-image caption"). Alternatively SPEC could accept a bound caption paragraph.
6. **`jr-count-hidden` counts DOM nodes.** A bound paragraph whose source returns '' still renders an empty `<p>`; the plan adds a generic "empty `ttm/*`-bound paragraph/heading renders nothing" filter. SPEC's 06 governing rule implies it; stating it would help.
7. **Colour rows below AA.** `js-words` (neutral-600 at 12px), `wr-chapter-num`/`ar-mostread-num`/`hub-part-num` (neutral-500 at 14–16px), `wr-serial-status` "Complete" (neutral-500), `nav-current` (accent) and the disabled pagination side (neutral-500) all fail axe `color-contrast` (serious), which the `a11y` row forbids. The plan asserts neutral-700/accent-700 as phase 2 did; SPEC §6.9 should carry the same override note.
8. **Hardening part 4 vs. the front-page lead.** §6.10 publishes part 4 without saying its category; a Technology post newer than part 3 would become the lead and break phase 2's front-page rows. The plan files part 4 under Security, dated today.
9. **Whole-row links with core blocks.** §6.4/§6.6 say the journal and archive rows are single links; core `post-title`/`post-excerpt` inside a Group cannot be wrapped in an `<a>` in block markup. Phase 1 shipped a linked title only. The plan converts the row Group into an anchor in a render filter (Decision "Whole-row links"); SPEC could name the mechanism or relax the row to "title is the link".
10. **`layout=list`/`rail` on `ttm/series-list`.** SPEC uses `layout=list` and `layout=rail`; the shipped enum is `rows|grid-2|grid-3|strip`. The plan renames `rows` → `list` and adds `rail` (rule 46 rename); SPEC §6.5/§6.6 could say so explicitly.
11. **Chapters heading text.** §6.5 wants "The Quiet Ledger — recent chapters" / "All 12" from `ttm/series-toc variant=chapters`, whose `heading` attribute today is a plain string. The plan composes the label in the block when `heading` is empty.
12. **"Stories" book form.** The mock's "Stories · 2019 · paperback" has no matching `Fiction\Books` form label; the plan renders `collection` as "Stories".
13. **`3b` series bar text.** The phone mock drops the word "Part" ("3 of 6"); markup cannot vary per viewport, so the phone keeps "Part 3 of 6" with the "Series" label and "View series" hidden.
14. **Inner masthead "one `<a>`".** Core `site-title` renders its own anchor; the "by Eric Mann" line is a sibling paragraph, not part of the same link.
15. **Nav close glyph.** With `hasIcon: false` the close button reads "Close", not "×" (01 §4.3); `hasIcon` governs both buttons.
16. **`§6.9 hub-progress-color`** assumes the featured series has both published and unpublished parts; the plan pins Hardening WordPress as `ttm_featured` in the seed so the auto-pick cannot drift to a completed series.
17. **Selectors row vs. block styles.** Rule 41 would flag every registered-but-unused `is-style-*` block style (04 §3 offers them in the inserter). The plan allow-lists them with the reason `editor block style (04 §3)`; SPEC could exempt `is-style-*` styles registered in `inc/block-styles.php` automatically.
