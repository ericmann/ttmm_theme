Derived from docs/SPEC.md v4.0 on 2026-09-22. SPEC.md wins over this file.

## Decisions
- Phases → SPEC §8's six phases (0 Harness, 1 The four defects, 2 Import and migration commands, 3 Classic conversion, 4 Live triage, 5 Backup drill/docs/close-out), in order, never merged. Each phase ends with a task that runs `npm run screenshots`, commits the PNGs under `docs/feedback/phase-4/`, pushes, and logs `Manual check: NOT VERIFIED (human)` naming what to open.
- Branch and repo hygiene → run branch `refine/<date>` from `main` (SPEC §7). Commit signing stays off (`commit.gpgsign=false`); never re-enable it. `FOUNDRY_FEEDBACK.md` is the owner's log: never stage, move, delete or gitignore-edit it. `docs/phase-1/`, `docs/phase-2/`, `docs/phase-3/` are history: never edit them. The WXR export `docs/ericmann039sblog.WordPress.2026-09-23.xml` is gitignored and is never read by a test, never quoted, never copied into a tracked path (rule 47).
- Q1 series map → `docs/migration/series.json` starts with exactly two entries: `boundless-summer-challenge` ("Boundless Summer Challenge", tags `boundless-summer-challenge` + `boundless`, nonfiction, complete) and `cryptopals` ("Cryptopals", tag `cryptopals`, nonfiction, complete). Schema: `[{"slug","name","tags":[…],"form","status","total"?}]`. `plan.sh` reads it through `node scripts/live/series-args.mjs` (no `jq` dependency).
- Q2 primary category → `primary:assign --from-yoast` first, then plain `primary:assign` (nav order) for the rest.
- Q3 excerpts → `migrate:excerpts --from=yoast`, non-Journal posts only, never overwrites. The `excerpt_length` key SPEC §5 calls "existing" does not exist in `Config.php` (the nearest is `journal.excerpt_max_words`); it is **added** as `excerpt_length => 55` ⚠️ ASSUMPTION in P2-03 and tuned in P2-08.
- Q4 images → Photon URLs whose host matches `migration.photon_origin` are rewritten to the origin URL; other listed hosts are sideloaded with `media_sideload_image()` (timeout `migration.image_timeout` = 20 ⚠️ ASSUMPTION); failures leave `src` untouched and flag `remote-image`.
- Q5 inert rows → imported Jetpack `feedback`, `custom_css`, foreign `wp_template`/`wp_global_styles`, `nav_menu_item` rows are left alone; `audit --summary` counts them by post type under an `inert-rows` line; nothing deletes them.

- Q7 exposure → documented only (MIGRATION.md §3.1): recommended Cloudflare Tunnel hostname behind Cloudflare Access (email OTP) with `blog_public=0`; alternatives public, or cluster-only via hosts file.
- Q8 zero-tag section → F16 stands.

The journal post header's "Journal RSS" link (`.ttm-journal-head__rss`, phase 3 §6.4) and the archive stats line's RSS link (`ar-stats-rss`) are part of the phase 3 contract and stay. ## Conventions
- Commit message: title `<ID>: <title>`; body `Goal:` / `Tests:` / `Interpretation:` / `Measurement:` (tuning only) / `Manual check:`; template in `CLAUDE.md`.
- After every task run `docs/foundry.json` `verify` (composer lint, composer test:unit, npm run lint, npm run test:unit, npm run build, forbidden-patterns) plus `extraVerify` for the touched prefixes. Docker is needed for integration, e2e, drill and live commands. Stale wp-env after a branch switch: `npx wp-env stop && npx wp-env start`.
- "Un-fixme row X" means: in `tests/e2e/fidelity.spec.mjs` change that row's `test.fixme(` to `test(`, delete its `// P<n>-<nn>` tag, and make it pass; never delete a row. Test names are `'<id>: <selector> @<viewport>'`. Text rows compare `textContent` normalised with `.replace(/\s+/g, ' ').trim()` (helper `text()` in `tests/e2e/lib/style.mjs`).
- Row-to-task map: `ar-filter-business`, `ar-filter-business-pos`, `ar-filter-sort-business` → P0-05 · `footer-copy`, `footer-nocopyright`, `footer-nav`, `footer-one-line`, `footer-font`, `footer-front-nors` → P1-01 · `toc-absent`, `bar-absent`, `aside-noseries-order`, `box-noseries`, `prevnext-auto-label`, `prevnext-auto-title` → P1-02 · `single-other`, `single-other-cats`, `single-other-fiction`, `single-other-heading` → P1-03.
- Colour vs a11y (phase 3 Decision, still in force): text under 18.66px asserted as `accent`/`neutral-500`/`neutral-600` in a mock is rendered and asserted as `accent-700`/`neutral-700`.
- Every CSS change goes under its `01 §4` numbered comment header in `ttm.css`; no hex literals; presets via `var(--wp--preset--…)`; `ttm.css` ≤ 63488 bytes.
- CLI command cores return `['ok' => bool, 'rows' => [...], 'messages' => [...]]` and are tested directly (`( new XCommand() )->run( $args, $assoc )`), never through `WP_CLI`. Every new flag supports `--dry-run` (rule 49) and has an integration test with `--dry-run` proving nothing was written.
- Shell scripts: `#!/usr/bin/env bash`, `set -euo pipefail`, every step prints `==> <step>` before and `<step>: <count> in <seconds>s` after; non-interactive (`--yes`, `--skip-plugins` never needed); pass `shellcheck` when it is installed (`command -v shellcheck && shellcheck scripts/live/*.sh`).
- Synthetic fixtures only (rule 47): a test that imitates live content uses invented sentences and the live markup *shape* (`[ref]…[/ref]`, `[cci lang="php"]`, Photon URLs), never a live post's text, title or slug. Titles/slugs of the owner's public posts may appear only in `docs/feedback/phase-4/LIVE-TRIAGE.md` and the committed live PNGs.
- Config keys are read as `Config::get( 'key', <default> )` with the default equal to `Config::defaults()` (`tests/unit/ConfigFallbacksTest.php`); `tests/unit/ConfigTest.php` lists every key.
- The `## Log` entry for a task lists rows un-fixme'd, interpretation choices, measurements, and `Manual check:` (or `none`).
