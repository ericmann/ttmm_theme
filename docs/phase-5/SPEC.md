# These Things Matter — Specification, phase 5 (demo content, Playground, open source)

Version: 5.0
Status: ready for flight (feature pass on branch `refine/*`, base `main`)

The Foundry planner reads this file in full and derives the build plan from it. Phases 1–4 (`docs/phase-1/` … `docs/phase-4/`) built the theme and plugin, made every screen match its mock, and proved the whole thing on the owner's real 889 posts (PR #14). The owner has decided to **build in public**: the repository is already public, and the next step is to make a stranger's first five minutes good. **This flight ships demo content with real photographs, a one-click WordPress Playground, README screenshots, and the licence hygiene of a proper GPL release**, modelled on how the WordPress default theme `ipsum` does it (`.github/blueprint.json` + `.github/ipsum-demo-content.xml` + `.github/*.png`). ## 1. Overview

### 1.1 Where we are

- `wp ttm seed` produces 107 synthetic posts across the seven sections, 7 series (4 nonfiction, 3 fiction), 2 books, the 4 pages and a sample verse, all from `docs/fixtures/seed/*.json`. It is deterministic (dates relative to `Clock::now()`, one second apart), and every screen's fidelity rows pass on it.
- Seed images are **generated placeholders** (rule 45: a neutral field with a diagonal band; covers a dark 2:3 field with the title). They are honest but make the front page look like a wireframe.
- The repo has GPL-2.0-or-later headers on `style.css`, `ttm-core.php`, `package.json` and `composer.json`, the Archivo fonts under OFL, but **no `LICENSE` file at root**, a 15-line internal README, no screenshots outside `docs/feedback/`, and the owner's name hard-coded in the footer line (`Values::footer_line()`) and the inner masthead ("by Eric Mann").
- `npm run screenshots` writes `docs/feedback/phase-4/*.png` for owner review; nothing is arranged for a reader.
- There is no Playground blueprint, no demo WXR and no release artefact; `plugins/ttm-core/build/` is gitignored, so a checkout without `npm run build` runs the editor on the fallback script and shows an admin notice.

### 1.2 What "good first five minutes" means

1. The README opens with screenshots of the front page and an article at 1280 and 390, and a **"Open in WordPress Playground"** link that lands on a populated front page: lead photograph, seven section cells, series strip, verse, journal rail, footer.
2. Anyone can `Tools → Import → WordPress` the demo WXR into their own site, or `npx wp-env start && npm run env:seed` locally, and get the same content.
3. Every photograph is CC0 or public-domain from **Openverse**, credited in a committed manifest; every line of demo prose is synthetic and licensed for reuse; the code licence is unambiguous.
4. Nothing about the demo needs the owner's live export, the owner's name, or a network call at build or test time, except the one-time curated Openverse fetch that a human runs.

"Done": `.github/blueprint.json` opens Playground on the populated front page (verified headless in CI with `@wp-playground/cli`); `.github/demo-content.xml` imports cleanly; `README.md` shows the eight `.github/screenshots/*.png`; `LICENSE` exists; `npm run lint` includes the demo and licence checks; `docs/fixtures/demo/CREDITS.json` covers every image; phase 1–4 suites still pass and the fidelity table is unchanged except the rows added in §6.9.

### 3.2 New rules

53. **Demo assets are licence-clean and provable.** Every file under `docs/fixtures/demo/images/` has a row in `docs/fixtures/demo/CREDITS.json` (`file, openverse_id, title, creator, creator_url, source, foreign_landing_url, license, license_url, width, height, bytes, sha256`), `license ∈ {cc0, pdm}`, and every row has a file; `scripts/check-demo.mjs` (in `npm run lint`) fails on any mismatch, on a licence outside the set, on a file over `IMAGE_MAX_BYTES`, or on a total over `IMAGE_BUDGET_BYTES`. No image reaches the repo any other way.
54. **The demo is offline and deterministic.** `npm run demo:build` makes no network request; `npm run demo:check` (Playground headless) fetches only from the checked-out tree or from `github.com`/`raw.githubusercontent.com`/`github-proxy.com`; the Openverse fetch (`npm run demo:fetch-images`) is a curated, human-run, rate-limited step whose output is committed, and it never runs in CI. Two `demo:build` runs on the same day produce identical files.
55. **The repository is publishable as it stands.** `LICENSE` (GPL-2.0-or-later full text) at root; `readme.txt` in plugin and theme with matching `License:` lines; `package.json`, `composer.json`, `style.css`, `ttm-core.php` agree on `GPL-2.0-or-later`; fonts keep `OFL.txt`; demo prose and images carry `docs/fixtures/demo/LICENSE.md` (CC0 for prose, per-image licence from CREDITS). `scripts/check-license.mjs` (in `npm run lint`) asserts all of this. No personal name is hard-coded outside `Config::defaults()` and the seed fixtures.
56. **Screenshots are generated, never hand-edited.** `README.md` embeds only files under `.github/screenshots/` written by `npm run screenshots -- --readme`; `check-demo.mjs` fails if the README references a missing file or the directory holds a file the README does not reference.
57. **The Playground path is a test.** `npm run demo:check` runs the blueprint headless against the current tree and asserts the front page, the article, `/series/` and `/writing/` (§6.4). It runs in CI on every push.

## 6. Interfaces

### 6.1 Openverse fetch (`npm run demo:fetch-images`, human-run)

- Input `scripts/demo/images.json`: an array of `{ file, query, orientation: "wide"|"tall"|"square", subject, exclude? }`, one per photograph the seed needs (§6.2 lists them). `file` is `demo-<slug>.jpg`.
- For each row: `GET https://api.openverse.org/v1/images/?q={query}&license=cc0,pdm&aspect_ratio={orientation}&size=large&mature=false&page_size=20`, pace `OPENVERSE_PACE_MS`, pick the first result with `width ≥ OPENVERSE_MIN_WIDTH`, `license ∈ {cc0, pdm}`, `filetype ∈ {jpg, jpeg, png}` and not previously chosen; download `url`; re-encode with `sharp` to ≤ 1600px wide JPEG q82 (no grayscale: the theme applies it in CSS; singles show colour); write the file and the CREDITS row (§3.2 rule 53) including the original `attribution` string. `--only=<file>` re-fetches one; `--dry-run` prints choices. Failures are listed, never silently skipped.
- Output is committed. Selection is reviewed by a human (Manual check) for subject fit and taste: newspaper-ish, muted, no faces of identifiable private people, no logos. The implementer runs it once and commits; the owner may replace any file by editing `images.json` and re-running `--only`.

### 6.3 Demo WXR and options (`npm run demo:build`)

2. `wp export --post_type=post,page,attachment --skip_comments --stdout` → post-process with `scripts/demo/lib/wxr.mjs` (pure, Jest-tested): rewrite every `wp:attachment_url` and every uploads URL in content and meta from the wp-env host to `https://raw.githubusercontent.com/ericmann/ttmm_theme/main/docs/fixtures/demo/images/<file>` (attachment file names are the demo file names, so the mapping is by basename); replace the author with login `demo`, display name from `site.author_name`, **no email**; drop `wp:base_site_url`/`wp:base_blog_url` hosts in favour of `https://example.com`; sort items by post ID; write `.github/demo-content.xml`. Post dates are whatever the seed produced that day (§9 Q3).
3. `wp ttm demo:options` → `.github/demo-options.json` (`blogname`, `blogdescription`, `timezone_string`, `permalink_structure`, `ttm_books`, `ttm_verse`, `ttm_verse_history`, `ttm_newsletter` with provider `none`).
4. Write `.github/blueprint.json` from `scripts/demo/blueprint.template.json` with the release tag from `--release <tag>` (default: the version in `plugins/ttm-core/ttm-core.php`, e.g. `v0.2.0`).
5. `scripts/check-demo.mjs` validates the three outputs: the WXR parses, item count equals the seed's, every attachment URL's basename exists in `docs/fixtures/demo/images/` and CREDITS, no `localhost`, no email, options JSON has the listed keys.

Term meta: the core exporter writes `wp:termmeta`, so series status, form, totals and next dates travel in the WXR. If the Playground importer drops them, the blueprint's `wp-cli` steps below restore the derived state and `demo:verify` fails loudly on missing term meta so the planner sees it in Phase 2.

## 9. Open questions

| # | Question | Decision (default) |
|---|---|---|
| Q1 | Use the owner's live posts in the demo? | **No.** Demo prose stays synthetic (the seed), licensed CC0, so the demo is redistributable and rule 47 stays simple. The owner may later replace individual posts by hand on their own site. |
| Q2 | Licence set for photographs | CC0 and Public Domain Mark only. CC-BY would work with the theme's captions, but credit-in-caption fights the editorial caption the mocks show. Credits still recorded and published. |
| Q3 | Demo dates | Relative to the build day; the site is designed to look finished on a quiet month (F7, F9, F22). `demo:build` is re-run whenever the fixtures change; no date pinning. |
| Q4 | Where the demo lives | `.github/` for WXR, options, blueprint and screenshots (as `ipsum`); `docs/fixtures/demo/` for images and credits because only `docs/fixtures/` is mounted into wp-env. |
| Q5 | Plugin/theme source for Playground | Release assets with `build/` included, via `github-proxy.com`. Installing from the branch would run the editor on the fallback script and show the build notice. |
| Q6 | Owner name | One `Config` key pair; default stays the owner. Not a settings screen (out of scope). |
| Q7 | Image processing dependency | `sharp` as a devDependency, used only by the human-run fetch and the screenshot optimiser; the plugin and theme never depend on it. |
| Q8 | Screenshot device frames like `ipsum`'s composites | No composites; plain full-page PNGs in a table. Simpler to regenerate and rule 56 can verify them. |
