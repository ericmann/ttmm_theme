Stop trusting the database: signing your options table

A compromised admin account can rewrite wp_options without touching a single file. Here is how to detect it — and why your file-integrity scanner never will.

By Eric MannSeptember 19, 202614 min read
wordpressphpintegrity

Every WordPress hardening guide begins the same way: lock down file permissions, disable the theme editor, verify core checksums. Good advice. All of it protects the filesystem — and none of it protects the thing that actually runs your site.

The options table is executable configuration. active_plugins, siteurl, cron schedules, rewrite rules — a hostile write to any one of these changes what your site does on the next request, and every scanner you own will report green.

What a signature buys you

Not prevention. A signature does not stop the write; it makes the write visible. On every load, WordPress recomputes an HMAC over the sensitive keys and compares it to the stored one. Mismatch means someone changed the configuration through a path you did not sign.

add_action( 'init', function () {
    $keys  = [ 'active_plugins', 'siteurl', 'home', 'template' ];
    $blob  = wp_json_encode( array_map( 'get_option', $keys ) );
    $sig   = hash_hmac( 'sha256', $blob, OPTIONS_SIGNING_KEY );
    if ( ! hash_equals( get_option( '_options_sig', '' ), $sig ) ) {
        do_action( 'options_tampered', $keys );
    }
} );

Twelve lines. The interesting work is in options_tampered: what you do when the alarm fires is the actual security design.

“A file-integrity scanner watches the doors. The options table is a window that was never on the blueprint.”

Where to keep the key

Not in the database — obviously — and not in wp-config.php if you can avoid it. Part 2 covered rotation; the same discipline applies here. In part 4 we move the key to the environment and rotate it without downtime.

A rainbow over the rail yard

Walking back from the coffee place there was a full rainbow over the rail yard — the kind that touches down at both ends, so complete it looks staged. Two guys in hard hats stopped and took pictures. So did I. Nobody said anything, which felt right.

I have been thinking about attention lately, mostly because part 4 of the hardening series is about what you notice and what you don't. A signature on the options table doesn't prevent anything. It just makes a change visible to someone who is looking. Most of security is that: deciding, in advance, to look.

The rainbow lasted about four minutes. The rail yard has been there for a hundred years and I walk past it every day and I'm not sure I had ever really looked at it before. It has a water tower. Who knew.

Anyway. Good coffee. Back to the draft.

The coffee grinder as a threat model

Ran the burr grinder this morning and thought, as one does, about attack surface. The grinder has one job and one input. It cannot be talked into doing anything else. There is no admin panel.

Most of the software I inherit is the opposite: a thousand inputs, twelve jobs, and a settings page nobody has fully read. I don't think the answer is fewer features. I think it's knowing which of them are load-bearing.
